## 1. 要做什么

在「认识这个字」页面加两处朗读：

| # | 位置 | 交互 | 念什么 |
| --- | --- | --- | --- |
| 1 | 田字格下方工具条，**笔顺按钮左侧** | 点击 | 当前这个字 |
| 2 | 组词列表的每个词 | 点击 | 该词语 |

范围**不做**：描红页逐笔朗读、练习页题目朗读（本轮不做，理由见 §11）。

## 2. 三条技术路线的取舍

朗读必须有音频。先算清楚"把音频打进包里"这条路走不通：

```
生字 2099 个 + 组词 6940 条（去重 5406）= 7505 条音频
按每条 mp3 最短 6KB 估算：7505 × 6KB ≈ 44MB
按 12KB（更接近正常音质）估算：≈ 88MB
```

微信限制：**单个分包 ≤ 2MB，全部分包合计 ≤ 20MB**。当前项目总量 2573KB，即使只算生字（2099 条 ≈ 12–25MB）也直接超限。

| 方案 | 能用于生产 | 代价 |
| --- | --- | --- |
| A. 音频打进包内 | ❌ | 44–88MB，必然超限；且 2099 个字的录音无法自动生成 |
| B. **微信同声传译插件** | ✅ | 免费、无需后端、无需域名备案；但需后台添加插件 + 真实 AppID |
| C. 自建 TTS 后端 | ⚠️ | 要服务器、要备案域名、要处理并发与鉴权，只为一个朗读功能不划算 |

**选 B。**

## 3. 前置条件（只有你能做）

这是整个方案的硬门槛，代码写完了也绕不过去。

### 3.1 必须换成真实 AppID

`project.config.json` 当前是：

```json
"appid": "touristappid"
```

游客模式**加载不了任何插件**，`requirePlugin` 会直接抛错。必须换成你在 `mp.weixin.qq.com` 注册的小程序 AppID。

### 3.2 必须在后台添加插件

路径：小程序后台 → **设置 → 第三方设置 → 插件管理 → 添加插件** → 搜索「**微信同声传译**」→ 申请（一般即时通过）。

添加后，`app.json` 里才允许出现 `plugins` 字段：

```json
"plugins": {
  "WechatSI": {
    "version": "0.3.5",
    "provider": "wx069ba97219f66d99"
  }
}
```

> ⚠️ `version` 请以后台「插件管理」里显示的**最新版本号**为准，不要照抄文档。
> 版本号写错会导致编译期报"插件不存在"。

### 3.3 插件基本用法

```js
const plugin = requirePlugin('WechatSI');
plugin.textToSpeech({
  lang: 'zh_CN',
  tts: true,
  content: '长江',
  success(res) {
    // res.filename 是音频临时文件，喂给 innerAudioContext 即可播放
  },
  fail(res) { /* 降级 */ },
});
```

返回的是**临时文件**（不是公网 URL），所以要配合 `wx.createInnerAudioContext()` 播放。

## 4. 多音字：本方案最大的技术坑

微信插件不支持 SSML，也没有拼音标注参数，**无法指定单字的读音**。直接念「长」，引擎可能给 `zhǎng` 也可能给 `cháng`，大约 7% 的字会读错。

你选定的策略是「多音字改念一个读音匹配本课的组词」。我按真实数据验算了一遍，**覆盖率只有 65%**，需要额外补数据。

### 4.1 实测数据

```
多音字：146 个 / 2099（7.0%）
多音字读音槽位：301 个（一个字可能有 2–3 个读音，每个读音对应一课）

按「找一个拼音含目标读音的组词」匹配：
  命中  196 槽位（65.1%）
  未命中 105 槽位（34.9%），涉及 98 个字
```

严格匹配（字在词中的那一位置拼音正确）和宽松匹配（词里任意位置出现该读音）**结果完全一致**，都是 196。说明缺的不是匹配算法，是**数据本身没有那几个读音的组词**。

未命中的例子：

| 字 | 本课读音 | 现有组词 | 问题 |
| --- | --- | --- | --- |
| 长 | `zhǎng` | 长篇 `cháng piān`、长江 `cháng jiāng` | 4 个词全是 `cháng` |
| 还 | `huán` | 还有 `hái yǒu`、还是 `hái shì` | 4 个词全是 `hái` |
| 看 | `kān` | 看见 `kàn jiàn`、看到 `kàn dào` | 全是 `kàn`（看守才对） |
| 少 | `shào` | 多少 `duō shǎo`、不少 `bù shǎo` | 全是 `shǎo` |
| 中 | `zhòng` | 中央 `zhōng yāng`、中午 `zhōng wǔ` | 全是 `zhōng` |
| 大 | `dài` | 大话 `dà huà`、大叔 `dà shū` | 全是 `dà`（大夫才对） |

原因是 `meta.w` 每字最多只有 4 个组词（分布：1 词 239 字、2 词 276 字、3 词 187 字、4 词 1397 字），只覆盖了教材里最常见的读音。

### 4.2 三个选项

| 方案 | 覆盖率 | 代价 |
| --- | --- | --- |
| **B1** 只做自动匹配 | 65.1% | 剩下 35% 退回念单字，其中一部分会读错 |
| **B2** 自动匹配 + **补词表** | 100% | 人工补 98 条「字+读音 → 词语」，约 1–1.5 小时 |
| **B3** 只念单字，不做词 | — | 交互最一致，但 146 个多音字全部有读错风险 |

**建议 B2。** 补词表是一个独立的小数据文件，不进主包：

```
content/source/pronounce.json
{
  "长|zhǎng": "长大",
  "还|huán":  "归还",
  "看|kān":   "看守",
  "少|shào":  "少年",
  "中|zhòng": "打中",
  "大|dài":   "大夫"
}
```

构建时合并进 `meta.js`，按 `char + '|' + reading` 索引。查不到再退回自动匹配，最后退回单字——三层降级保证任何情况下都有声音。

> ⚠️ 补词必须由**懂拼音的人**过一遍。98 条里有不少是虚词和生僻读音（`了|liǎo`、`吗|má`、`单|chán`、`燕|yān`），我不要自作主张替你定。

### 4.3 另一种交互可能更简单

既然多音字最终念的是词，可以考虑**统一都念词**：

- 多音字 → 念匹配读音的组词
- 非多音字 → 也可以念第一个组词（让孩子听到字的用法）

好处是两次点击的行为一致，坏处是偏离了你说的"读这个文字"。**按你的原始描述做，多音字才念词**，非多音字念单字。

## 5. 接口设计

新增 `miniprogram/utils/tts.js`，单文件封装，页面只调三个方法。

```js
const tts = require('./tts');

tts.speak('长江', { kind: 'word' })   // 播放，返回 Promise<{ok, cached}>
tts.stop()                            // 停止当前播放
tts.supported()                       // 插件是否可用（用于决定按钮是否显示）
```

### 5.1 内部要点

| 关注点 | 做法 |
| --- | --- |
| 插件缺失 | `requirePlugin` 外面包 `try/catch`，标记 `available = false`，后续调用直接返回失败 |
| 音频对象复用 | 全页只创建一个 `wx.createInnerAudioContext()`，换 `src` 而不是反复创建（否则 iOS 上有内存泄漏与并发播放问题） |
| 结果缓存 | `Map<text, filename>`，同一个词第二次点不再请求网络 |
| 并发保护 | 正在合成时再点击 → 先 `stop()`，记录序号，忽略过期的 `success` 回调 |
| 失败降级 | 合成失败 → `wx.showToast({ title: '朗读暂时不可用' })`，不阻塞任何其他功能 |
| 生命周期 | 页面 `onUnload` / `onHide` 调 `tts.stop()` 并 `destroy()` 音频对象 |

### 5.2 为什么要缓存

`textToSpeech` 是网络请求，首次点击有 **300–800ms 延迟**。不做缓存的话，反复点同一个词每次都卡。

缓存上限设 200 条（Map 超过就删最早的），避免长时间使用后内存增长。

### 6.3 页面逻辑

`utils/detail-page.js` 加：

| 新增 | 内容 |
| --- | --- |

## 7. 预览环境必须一起改

**这是最容易翻车的地方。** 预览跑的是真实页面 JS，而浏览器里没有 `requirePlugin`，也没有 `wx.createInnerAudioContext`。不处理的话 detail 页一加载就白屏，现有 20+ 条断言全部失败。

`preview/runtime.js` 需要补三样：

| 补什么 | 目的 |
| --- | --- |
| `window.requirePlugin = () => mockPlugin` | `textToSpeech` 返回假 filename，并记录调用次数，供断言检查 |
| `wx.createInnerAudioContext()` | 返回带 `play/stop/destroy/onEnded` 的假对象 |
| `app.json` 的 `plugins` 字段容错 | 预览不校验插件，缺了也不报错 |

同时暴露 `window.__ttsLog`（记录每次合成的文本），断言里就能验证"点『读』→ 念的是这个字"、"点组词 X → 念的是 X"。

## 8. 测试方案

### 8.1 单元测试 `tests/tts.test.mjs`（新增）

| 用例 | 断言 |
| --- | --- |
| 缓存 | 同一文本调用两次，插件只被调用 1 次 |
| 并发 | 连续点两次，只有最后一次生效，不出现两段音频叠加 |
| 插件缺失 | `requirePlugin` 抛错时不崩，`supported()` 返回 false |
| 合成失败 | 返回 `{ok:false}`，不抛未捕获异常 |
| 缓存上限 | 超过 200 条后淘汰最早的一条 |
| 多音字选词 | `长|zhǎng` → 念「长大」；`长|cháng` → 念「长江」 |
| 三层降级 | 补词表缺失 → 用自动匹配；自动匹配也失败 → 念单字 |

### 8.2 数据校验（加进 `build-data.mjs`）

| 校验 | 规则 |
| --- | --- |
| 补词表自洽 | `pronounce.json` 的每个 key，字必须在字库里，读音必须在该字的 `readingsOf` 里 |
| 补词表有效 | 每个补词的拼音必须真含目标读音（否则补了也没用） |
| 覆盖率报告 | 构建时打印"多音字读音覆盖率 xx%"，低于阈值（如 95%）时警告 |

### 8.3 预览断言（加进 `scripts/preview.mjs`）

```
· 朗读按钮存在且在笔顺左侧
  ✓ 认字页朗读  按钮位置 x=... < 笔顺 x=...
· 点击「读」念的是这个字
  ✓ 单字朗读  合成文本「日」
· 多音字念匹配读音的组词
  ✓ 多音字  长(zhǎng) → 合成「长大」
· 点击组词念该词
  ✓ 组词朗读  合成「日出」
· 插件不可用时给出提示
  ✓ 降级  显示「朗读暂时不可用」，页面其他功能正常
```

### 8.4 静态检查

`scripts/lint.mjs` 加一条：`app.json` 里如果配了 `plugins`，`utils/tts.js` 必须存在；反之 `tts.js` 存在则 `app.json` 必须配 `plugins`。防止"代码写了但忘配插件"。

## 10. 风险登记

| # | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R1 | **插件未配置 → 功能完全不可用** | 高 | 代码写成"检测不到插件就隐藏按钮"，不影响其他功能；文档写明前置步骤 |

| R7 | 插件计入包体积 | 低 | 需在真机实测确认（plugin 体积通常计入总包）；当前余量 20MB 充足 |

## 11. 明确不做

| 不做 | 原因 |
| --- | --- |
| 描红页逐笔朗读 | 笔画动画期间（620ms/笔）穿插音频，节奏容易打架，且对写字帮助有限 |
| 练习页题目朗读 | 5 种题型文案各异，要设计一套朗读脚本，工作量翻倍，本轮不值 |
| 语速 / 音量调节 | 插件不支持；增加界面复杂度对孩子不友好 |
| 跟读评分 | 需要录音 + 语音识别，是另一个量级的功能 |
| 离线朗读 | 必须联网，插件本质是在线合成 |

## 13. 需要你决定的两件事

1. **补词表做不做？** 不做则多音字 35% 退回念单字、可能读错；做则需要你或懂拼音的人定 98 条内容。
2. **插件配置谁来做？** 后台添加插件 + 换真实 AppID 只能由你操作，代码写完后不配就是"按钮不显示"的状态。

确认这两点后即可开工。
