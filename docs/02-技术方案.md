# 小小识字家 · 技术方案

> 目标：把 1600 个汉字的笔顺数据塞进 2MB 主包限制里，并在低端安卓机上流畅地"看动画 + 手上写"。

---

## 1. 技术选型

| 选择 | 理由 | 放弃了什么 |
| --- | --- | --- |
| 原生小程序（WXML/WXSS/JS） | 无构建、无依赖、包体最小；审核稳定 | Taro / uni-app 的跨端能力 |
| Canvas 2D（`type="2d"`） | 逐笔动画需要按帧重绘；SVG 路径在小程序里无法逐笔控制 | 用 WXML 画笔画（做不了半笔动画） |
| 数据预编译成 JS 模块 | 免去运行时解析 6.5MB JSON；`require` 即用，可按册懒加载 | 运行时 `wx.request` 拉 JSON（首屏慢、要配域名） |
| 纯本地存储 | 无需登录、无后端成本、审核简单 | 多设备同步 |
| 分包 + `preloadRule` | 主包 464KB，笔顺数据 1.4MB 放分包，进首页就预载 | 全放主包（超限） |

**没有 npm 运行时依赖**，`node_modules` 只用于开发和验证（`@napi-rs/canvas`、`puppeteer-core`）。

## 3. 数据管线

### 3.1 源数据

| 来源 | 内容 | 形态 |
| --- | --- | --- |
| 统编版生字表（经 [fsiceangel/zishi](https://github.com/fsiceangel/zishi) 整理） | 册/单元/课/字、拼音、部首、组词 | `content/source/{volumes,chars,words,radicals}.json` |
| [Make Me a Hanzi](https://github.com/skishore/makemeahanzi) | 每字的分笔 SVG 路径 + 笔画中线（median） | `content/source/strokes/*.json`（1600 个） |

### 3.2 构建流程（`scripts/build-data.mjs`）

```
读取 volumes/chars/words/radicals
   ↓ 校验：4 册字数必须为 300/400/450/450，共 1600；每课字不重复
读取 strokes/<char>.json
   ↓ 校验：strokes 条数 == 笔画数 == medians 条数（不一致直接构建失败）
解析 SVG path（M/L/Q/C/Z）→ 量化坐标
   ↓
编码为二进制 → base64 → 写成 JS 模块
   ↓
写入 miniprogram/data/{catalog,meta}.js 与 packageStrokes/data/strokes-*.js
   ↓
content/build/stats.json（体积与统计，供 lint 与文档引用）
```

构建脚本是**幂等**的，并会在数据异常时 `exit 1`。已知的两处数据补丁写在 `WORD_PATCH`（`唉`、`哦` 缺组词）。

### 3.3 二进制格式

每个字一段 base64，解码后：

```
u8   version          // 2
u8   strokeCount      // 笔画数 n
n × {
  u16  byteLength     // 该笔路径字节数
  u8[] path           // 见下
}
u8   medianCount      // 中线数（= n）
n × {
  u8   pointCount
  u8[] points         // [x, y] 成对
}
```

路径字节：`op` + 参数，坐标是 `round(原坐标 / 6)` 的 u8（原图 1024×1024，量化后 0–170，解码乘回 6 → 误差 ≤ 3/1024 ≈ 0.3% 字高）。

| op | 含义 | 参数 |
| --- | --- | --- |
| 0 | moveTo | x, y |
| 1 | lineTo | x, y |
| 2 | quadraticCurveTo | cx, cy, x, y |
| 3 | bezierCurveTo | c1x, c1y, c2x, c2y, x, y |
| 4 | closePath | — |

**为什么用 6 而不是 4**：v1 用步长 4（0–255 装不下 1024，只能截断）。改为 6 后坐标范围 0–170，完全落在 u8 内，且体积下降约 1/3；渲染时按字高 320px 计算，3/1024 字高 ≈ 1px，肉眼不可见。

### 3.4 体积账本

| 文件 | 大小 | 位置 |
| --- | --- | --- |
| catalog.js | 43 KB | 主包 |
| meta.js | 303 KB | 主包 |
| strokes-1a.js | 204 KB | 分包 |
| strokes-1b.js | 363 KB | 分包 |

## 4. 渲染引擎（`hanzi-canvas.js`）

### 4.1 坐标映射

```
pad = box * 0.035                       // 四周留白，避免笔画贴死田字格
px(v) = pad + v / 1024 * (box - 2*pad)  // v ∈ [0, 1024]
```

### 4.2 绘制能力

| 函数 | 用途 |
| --- | --- |
| `drawGrid(ctx, box, ox, oy)` | 田字格：外框 + 十字虚线 |
| `drawStrokes(ctx, data, box, ox, oy, opts)` | 画 `completed` 笔；`partial` 控制当前笔的进度（虚线 lineDash 模拟运笔） |
| `drawStrokeHighlight(ctx, data, i, ...)` | 单笔高亮（描红答对后吸附到标准笔形） |
| `drawStrokeNumbers(ctx, data, ...)` | 起笔序号圆点 |
| `medianPoints(median, box, ox, oy)` | 中线转画布坐标（评分用） |

**dpr 处理**：`canvas.width = cssWidth * dpr`，然后 `ctx.scale(dpr, dpr)`，之后所有绘制都用 CSS 像素，避免高分屏模糊。

### 4.3 动画播放器（`animation.js`）

```
每笔：PER_STROKE_MS = 620ms 逐帧推进 partial 0→1
      STROKE_GAP_MS = 140ms 停顿
帧驱动：canvas.requestAnimationFrame，降级 setTimeout(16)
速度倍率：0.5x / 1x / 1.5x（设置项）
```

支持 `play()` 全字、`playStroke(i)` 单笔（描红提示用）、`stop()`。

## 5. 描红评分（`trace.js`）

### 5.1 五个维度

| 维度 | 权重 | 含义 |
| --- | --- | --- |
| startScore | 18% | 起笔点是否在中线起点附近（容差 `2.2 × tol`） |
| endScore | 12% | 收笔点是否在中线终点附近 |
| coverScore | 32% | 用户每个点到中线的平均距离 |
| reachScore | 26% | 中线每个点到用户笔迹的平均距离（防止"只点一下"） |
| lengthScore | 12% | 笔迹长度 / 中线长度 ∈ [0.75, 1.45] 得满分 |

```
score = round(100 × Σ wᵢ · sᵢ)          // 各分项先 clamp 到 [0,1]
```

`tol = min(宽,高) × 0.075`（320px 画布约 24px），随屏幕自适应，小屏不苛刻。

### 5.2 判定

```js
ACCEPT = 42            // 单笔通过线
snap   = score >= 68   // 高分吸附成标准笔形，低分保留手写痕迹
reason = start | off | short | empty   // 对应四句人话提示
```

整字评分 `scoreChar`：`0.85 × 平均分 + 0.15 × 最低分`，避免某一笔乱画还拿高分。星级：≥85 三星，≥65 两星，≥40 一星。

### 5.3 为什么用"点到折线距离"而不是模板匹配

- 不需要训练、不依赖设备差异；
- 6–8 岁孩子写得歪是常态，模板匹配对笔画粗细、倾斜极敏感；
- 每个维度都能直接翻译成一句提示语（起笔不对 / 写歪了 / 没写全），这是教育产品最需要的。

## 6. 出题器（`quiz.js`）

5 种题型，全部由 `mulberry32(seed)` 驱动，同一 seed 结果可复现（便于测试与"再来一组"）：

| 类型 | 题干 | 选项 |
| --- | --- | --- |
| `pinyin2char` | 看拼音选字 | 4 个字形相近/同册的字 |
| `char2pinyin` | 看字选拼音 | 4 个拼音（含声调） |
| `fillWord` | 词语填空（`天__`） | 4 个字 |
| `strokeCount` | 这个字有几笔 | 4 个数字 |
| `char2word` | 哪个词里有这个字 | 4 个词 |

干扰项优先取**同册**的字，保证难度合理；`uniqueOptions` 保证选项不重复；每题附解析（读音 + 部首 + 笔画 + 组词）。

## 7. 间隔重复（`srs.js`）

Leitner 盒子，间隔表 `[0, 1, 2, 4, 7, 15, 30, 60]` 天：

```
learn()     首次学习 → box 1，明天复习（重复调用不降级）
grade(+1)   答对 → box+1（上限 7）
grade(-1)   答错 → box>=3 退到 1，否则退到 0
markKnown() "我认识它了" → 直接 box 4
mastered    box >= 5（≥15 天间隔）
```

`due` 存的是"日期序号"（`day.js` 用本地时区算的整数天），避免时区与夏令时问题。

## 8. 存储设计

全部本地，键前缀 `hanzi:v1:`：

| 键 | 内容 |
| --- | --- |
| `progress` | `{ [char]: {box, seen, ok, miss, due, last, known} }` |
| `wrong` | 错题：`{ [char]: {count, lesson, last} }` |
| `write` | 描红记录：`{ [char]: {best, stars, times, last} }` |
| `stats` | 每日统计：`{ [dateKey]: {learned, quiz, correct, write} }` |
| `settings` | `{ dailyNew, speed, sound }` |
| `last` | 上次学到的课（用于"继续学"） |

`store.js` 在小程序里走 `wx.*StorageSync`，在 Node 测试里自动退回内存对象 —— 同一份 `progress.js` 既能跑测试也能跑真机。

## 9. 性能

| 关注点 | 做法 |
| --- | --- |
| 首屏 | 首页只 `require` catalog + plan + progress，不碰笔顺数据 |
| 分包预载 | `preloadRule`：首页/课文页进入时后台预载 `strokes` 分包 |
| 按册懒加载 | `stroke-store.js` 只 require 当前册的 `strokes-*.js`，其余不加载 |
| 解码缓存 | `stroke-store` 内存缓存已解码的字，重复进入不重复解码 |
| 重绘 | 描红每帧只 `clearRect` + 重画已确认笔画，笔画数 ≤ 24，无压力 |
| 长列表 | 课文页最多 12 格、单元页 ≤ 8 行，不做虚拟列表 |

## 11. 已知限制与后续

1. **描红只在 canvas 内判定**：手指滑出画布会丢点，真机上已用 `catchtouchmove` 兜住，但极端快速书写可能漏点。
2. **无音频**：拼音与组词只有文字，v1.1 再加 `InnerAudioContext`。
3. **字体**：田字格旁的字用系统楷体（`Kaiti SC`），iOS 效果好，部分安卓机型会退到黑体；打包楷体字库要 +3–6MB，暂时不做。
4. **笔顺数据来自开源项目**，与教材印刷体可能在个别字上有细微差异（如"竖钩"的钩长），已在"关于"页说明。
